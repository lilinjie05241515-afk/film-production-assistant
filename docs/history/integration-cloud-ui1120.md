# 1.12.0 云稿工作流程界面

本轮修改 `plugin/ui/board.html`，继续使用原生插件看板与宿主消息，不引入云端凭据、网页服务或后台同步。

## 使用入口

- 创作内容列表显示该准确成果的云稿状态；阅读页显示上次读回版本、未闭合任务和“读取并打开本篇云稿”“继续处理云稿”。
- “云端工作稿”分类增加按成果与 scope 的持久任务列表。已有 `cloud_working_draft` 快照及通过总稿仍分别展示。
- 新版的正文“云端工作稿”入口只打开管理窗口；其中“同步这份完整稿件”才准备本地云任务，“读取并关联已有工作稿”才请求宿主按完整观察关联。分类总稿不是单章整页替换目标。
- “工作稿同步方式”表单明确保存 `round_end` 或 `local_only`。切换仅本地不会删除已有云稿或未知请求；本地记录保留用于恢复。

## 保存与宿主交接

正文编辑器默认展示“保存后继续同步到同一云稿”，也可选择“本次只保存在本机”。项目策略为仅本地时，按轮选项禁用。初稿保存附带 `cloud_update.trigger=full_draft`；明确修订附带 `confirmed_revision`；单次或项目仅本地附带 `local_only`。来源为 `panel`，保留实际提交操作与修改说明。空白文本、结构化记录、灵感/规划记录和旧运行快照不添加自动云触发。

`artifact.save` 与 `task.submit` 先通过原 WriteJournal 保存并读回。本地成功回执包含云任务时，再 `cloud.read` 核对项目、文档、成果范围、任务号和准确版本/摘要，才给当前宿主发送接续请求。请求只传准确引用，正文由宿主读取准确版本，不重复复制长文。检查点本身不触发云任务。

宿主按 `references/cloud-round-workflow.md`、当前动作契约与真实 Page 工具推进：已有 Page 先读取当前内容，未知结果先核对，领取与外部操作分开，只有完整匹配读回才记录同步。看板不自行写 `cloud.record` 或假造 Page 结果，不调用审批，不创建其他聊天或向其他聊天发送消息。

云交接失败时保留已经成功的本地候选，显示“云稿待处理”。同一面板再次请求同一任务时仅核对原协调结果，不重复要求创建或编辑。关闭重开后依靠后端持久任务和领取检查恢复，而不是依赖面板内存推断外部执行结果。原本机保存结果未知时继续使用原操作号；核对成功后可接续返回的云任务。

## 范围与读取边界

文档关联以 `artifact_id + scope` 精确匹配。打开本篇云稿只读取并打开已有关联 Page，不准备任务、创建或编辑。项目身份在异步读取返回后再次核对；错误项目、范围、请求身份、重复任务记录、缺少准确摘要或与预期版本不一致时不发送宿主请求。

旧阅读版本不能通过“同步这份完整稿件”替换更新的本地候选。仅本地模式下可以核对旧未知结果，但不请求另一轮云写入。已同步标签只代表记录中的那次完整读回一致，不能证明云端之后未被手工修改，也不代表审核通过。

## 验证

`tests/test_cloud1120.cjs` 直接加载实际 board 脚本，使用独立 TEST 数据、模拟 DOM 与 RPC。覆盖正文保存和任务提交的触发、仅本地、首次完整稿、准确引用交接、本机成功而宿主响应丢失、旧任务核对、每成果范围、旧阅读版拒绝、错误/迟到项目回执、重复点击、显式设置与关联。

该测试不连接真实 Pages，不创建、打开或修改真实作品，不代表原生客户端的实际点击/云读写验收。
