# 1.14.0 统一编剧与美术总监

本版在正式1.13.0基础上合入编剧增量，同时提供完整写作、导演反馈修订、全片视觉定调和基准维护。软件统一发布、安装，作品继续使用既有身份、准确版本和云稿关联。

## 专业分工

编剧统一处理原创剧本、小说改编、可选小说和修订。默认优先AI短剧的可演分场正文，按明确项目形式写作，不强制固定时长、爽点结构或先写小说。直接剧本路线可以从正文开始，源剧本底稿可选；已有项目不会因升级自动换路线。小说与改编完整方法保留在screenwriter/methods中，旧名称继续解析到相应模式。

美术总监延续全片色调、场景风格、时代质感、主选与备选、场景资产设计指导和实际媒体复核。首次一主一备，基准内局部修改直接接续，不强制重新定调。整体风格、时代或已选角色外观变化仍提交具体方案供用户决定。详见 [美术首版](integration-1.13.0.md) 与 [美术接口](integration-art-1.13.0.md)。

总控负责项目、准确版本、任务、对话及交接，导演负责具体拍法、表演、剪辑与声音，编剧负责故事与文本，美术负责视觉体系。专业意见不自动改变其他职责已经采用的成果。

## 导演意见与完整修订

`film_screenwriting` 提供read、record、resolve；登记准确剧本版本、范围、原句、问题、预期效果、必须保留内容和影响。suggestion为可选，空建议字段应省略。普通意见可以在授权范围内形成完整修订候选；涉及重大剧情、人物动机关系、结局或世界规则的变化，先交影响与候选方案，未获选择不写入主修订稿。

意见处理要关联同一成果、同范围、较新且当前最新的完整修订版本，保存处理历史。记录“已处理”与保存正文、独立复核、用户采用分开。staging意见仅改导演拍法时不强制伪造一份剧本修订。详见 [编剧工作说明](integration-screenwriter-overview-1.14.0.md) 与 [意见接口](integration-screenwriter-1.13.0.md)。

## 与美术和云稿的共同约束

编剧产生剧本新候选时，已采用美术基准保持原版本；剧本正式采用后，已登记依赖按原机制提示需复核，由实际专业审查判断变更范围，不自动整片返工或豁免。

编剧任务自动引用全剧风格时，后端检查该风格是否间接依赖本次输出成果。若形成回路，准确全文、版本、摘要、原因及依赖路径保留为冻结创作参考，随任务与检查点锁定并在提交时复核；没有回路则保留普通依赖。创建时尚未指定输出身份的任务在提交时补查，用户明确给定的循环依赖不会被静默删除。整体基准变更或其他来源过期仍阻止旧任务继续写入。

页面编辑文字通过 `artifact.save` 的可选 `use_current_style:true` 委托后端处理自动风格引用；前端不把自动建议冒充用户明确输入。原deps与准确参考保留，普通保存不能伪造或篡改冻结来源。未使用此参数的旧API保持既有行为；已有来源记录继续核对。

剧本采用导致美术基准需复核时，先读取完整差异和云稿。基准内修订使用 `art.revise` 的可选 `rebase={previous_inputs:[REF],inputs:[REF]}`，完整冻结原依赖，只更新同身份且已采用的准确剧本版本，不增加、删除来源或顺带更换其他专业输入。无需修改视觉正文时可以空edits，确需修改时保留其他全文；云端手改须先完整保留并逐项解释。新候选独立采用前，旧基准仍是原采用指针并保持需复核。重大视觉变更继续回到方案比较与用户选择。已有旧版本的明确硬依赖回路不自动迁移、清状态或补造兼容结论。

美术修订仍保留统一style_bible的稳定身份及非视觉全文，最新工作稿、完整修订来源和已采用基准分别核对。导演意见记录不取代全剧风格；美术方案选择也不批准剧本。

完整初稿和每轮明确修订按当前round_end/local_only接续同一云稿，先保留手改，完整读回后报告同步。讨论、检查点、意见登记、方向选择不单独触发云写入。未知外部结果继续恢复原请求，不因合并版本而重建聊天或Page。

## 运行与兼容

八个专业模块：编剧、美术总监、导演、特效、资产与视频提示词、影视分析、灵感探索、需求规划。四个公开技能：总控、编剧、美术总监、脑暴接口（仍只准备外部交接）。二十四个MCP工具包括film_art与film_screenwriting。版本以filmprod.__version__为运行来源，装配校验清单并验证MCP/看板身份一致。

旧运行目录及任务execution_lock保留，不能重写旧锁让任务伪装成新版；需要匹配旧环境接续，或明确结束后新建。新版安装不自动扫描或迁移真实作品。只在隔离TEST和synthetic数据中验收，程序与模拟UI通过不等于真实作品、原生界面或审美采用验收。
