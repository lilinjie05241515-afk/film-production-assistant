# 1.19.0 Blender 预演与看板审看 V1

基于已冻结 Windows 1.18.0。八项专业方法完整保留，导演增加包内 Blender 执行器及预演交接。没有第二套作品登记，没有后台聊天/渲染调度。个人工作区默认授权不进入发行包。

`previs.register` 仅模型工作对话可调用；通过原 Registry 事务登记导演任务、精确剧本/导演来源、计划、工程、完整镜头视频、俯视视频和渲染回执。所有文件在项目内，并校验完整 SHA-256。同一序列使用稳定镜头编号、固定角色身份/颜色；同一 revision 覆盖版本、反馈与选择，原 op_id 复用保持幂等，过期 revision 拒绝。导演任务仍受原执行锁和冻结脚本输入保护。

`film_board_manage` 增加固定白名单 `previs.read / previs.chunk / previs.feedback / previs.select`。前两项只读；反馈只追加原话和版本/镜头/时间；选择只写用户明确点击的准确范围。注册、渲染、任务创建、消息发送不在 UI 白名单。测试项目自动 synthetic；这不证明真人采用。

首版没有 HTTP 媒体服务器。`previs.chunk` 通过 MCP 返回最多 192 KiB 的文件块，界面校验身份、偏移、总长与完整 SHA-256，然后用 Blob URL 播放完整 H.264 MP4。每个视频上限 128 MiB；没有截取前 12 秒的后备。实际 MCP 宿主须另行核验 CSP、消息大小、Blob 媒体支持，测试桥接页不能替代。关闭审看释放 Blob 并停止媒体。

看板入口：创作任务 → 导演与特效 → 对应任务 → 预演审看。提供完整播放、暂停、时间线、单镜定位/循环、0.25/0.5 倍速、镜头/俯视/同步双画面、角色图例、修改说明、来源、问题记录和版本比较。视频定位为普通 seek，不声称逐帧。两版独立控制，按稳定镜头起点定位，不按同秒冒称动作对齐。

最新候选、镜头选择、整段通过分开。混选显示 assembly_required，保留历史整段通过指针；`compose.py` 明确执行时生成新计划，检查空间、角色及切点位置/朝向，冲突停止。连续新版渲染、登记后仍须用户整段选择。依赖出现新版时保留历史、提示导演复核，禁止新增通过记录。修订时从 Registry 取原话，先更新导演方案，再把新准确引用与反馈 IDs 登记回同一序列。

程序校验、渲染回执、抽帧画面观察、浏览器测试桥接、原生 MCP 宿主验收与真人采用必须分别报告。`tests/previs_browser_harness.py` 是独立 TEST 本地验证工具，不打入发行包，不开放真实作品。
