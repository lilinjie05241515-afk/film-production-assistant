# 1.7.2 资产分类与 Markdown 阅读

本补丁针对资产管理缺少分类展示、导入的 Markdown 正文显示原始符号的问题。原八项专业方法保持冻结；本版调整阅读与资产管理能力，不迁移或扫描真实作品。

## 资产分类

资产按显式 `metadata.asset_type` 分为 character（人物）、scene（场景）、prop（道具）、other（其他）、unclassified（未分类），提供全部视图、分类计数和空态。缺失或无法识别的历史分类只读显示为未分类，不凭名称或正文猜测。旧 kind=prompt 仍属于资产；人物小传等其他内容不会自动移入资产分类。

资产档案与提示词按精确版本显示初稿、已通过、待审修改和需复核；图片登记单独显示，不把文件登记当作采用。档案分类随候选版本保存；图片分类使用媒体摘要和分类修订号避免错改及并发覆盖。修改分类不会重写原件、取消批准或自动批准其他内容。

## Markdown 阅读与原文

正文为字符串时支持常见 Markdown 标题、段落、强调、列表、引用、代码、表格和链接的阅读排版。阅读视图与原文视图可切换；编辑保留源文本并可预览，复制源文不从渲染后的 DOM 提取。未经修改的原文不因打开或切换视图改变换行。结构化对象继续保留字段与数组，只对明确的 text/markdown 正文字段作局部呈现，不随意拼接对象为新的正文。

HTML 作为文字保留，不执行脚本或事件；图片引用不会自动请求远程图片。链接只允许安全的明确协议，其他引用保留可读文字。当前范围是常见 Markdown 阅读，不声称涵盖完整 CommonMark/GFM 或第三方 Markdown 扩展。

导入的 Pages 工作稿、候选、已通过内容与历史版本都保留原本身份和状态。显示改进不意味着重新导入或重新批准。AI 视频提示词仍复制准确正文，不把排版、版本说明或来源元数据混入提示词。

`document.export` 为只读的准确版本正文导出接口，要求 expected_project_id、artifact_id、version。返回可下载的 UTF-8 .md 正文、文件名和摘要，不附加阅读包装、不修改注册内容；原有字符串中的 CRLF/LF 保留。结构化内容不伪装成 Markdown 正文。面板请求下载后，不能在未观察操作系统文件时宣称文件已保存到某个本机目录。

## 验证及版本接续

新增后端/界面测试使用 test_only 合成项目，覆盖显式分类与未分类、候选/通过并存、分类冲突、Markdown 常见块与转义、原文保真、历史导出、异步项目切换及既有审批边界。验证证据区分代码交互测试、真实 stdio、实际宿主安装与原生可视操作。

本地静态 HTML 的可视预览若受到宿主浏览器 URL 协议策略阻止，不转换网络入口或使用其他浏览器绕过；如未完成原生可视验收，应在交付中明确记录。

作品数据 schema 仍为 2。系统和模块执行锁按精确版本保持，旧任务不能擅自改锁后在新版提交。程序发行、安装配置、catalog 和作品独立；本地安装及活动版本不等于已有聊天已加载。新版在目标聊天通过 film_health 核对后使用。写入 1.7 规划记录的作品继续遵守 1.7.1 文档中的配套快照回退边界。
