# 1.9.4 Markdown 本机导出

本版处理点击「导出当前篇 .md」后没有可见结果的问题。旧入口在取得原文后请求嵌入页面执行 Blob 下载，没有本机文件落盘回执。新入口使用本机 stdio 保存派生文件，并显示真实保存位置；不再把浏览器下载请求当作文件已保存。

## 保存范围与回执

导出仍绑定用户选中的准确作品、成果 ID 和版本。先通过 `document.export` 核对完整字符串正文、UTF-8 字节、大小与摘要，再将同一准确引用及 `expected_sha256` 交给 `document.save`。保存请求还带 `expected_project_id` 和原 `op_id`；不能用当前页面的其他章节、最新候选或渲染后的 HTML 代替所选正文。

本机文件写到明确作品目录的 `11-导出/Markdown` 中。文件名由安全化成果 ID、版本及正文摘要确定；请求不能指定任意目标目录。字符串原文中的 BOM、CRLF/LF、中文和符号保留，输出编码为 UTF-8，不附加标题包装、来源说明或审核标记。原文为空时可以保存零字节正文，零字节不表示读取失败。

`document.export` 继续保持只读的正文返回协议。`document.save` 仅新增派生文件：通过 `Registry.open_readonly` 读取已有 schema 2 项目，不创建或迁移作品登记库，不保存新候选、不更改通过指针、任务、事件或元数据。其 `op_id` 用于识别导出请求；它不借用项目编辑事件来声称内容已变更。

保存不能覆盖已有不同内容。确定的同名文件已存在且回读字节一致时复用；目录重解析点、软链接、路径逃逸、目标冲突或写入失败都不能返回成功。只有实际文件完整回读的摘要和大小与源文相符，才返回 `saved_verified=true`、准确成果引用、作品身份、原操作号、完整 `local_path`、文件名、字节数、摘要及 created/reused 状态。

文件和父目录在各关键步骤重新检查，拒绝检测到的链接或路径变化。这是本机导出的一致性检查，没有持有整条路径的操作系统目录句柄锁，不能当作防御同权限恶意进程持续并发替换目录的安全沙箱。成功回执记录核验时的文件状态，之后手动编辑派生文件会使它与原文不同，再次导出将拒绝覆盖。

## 界面反馈与恢复

点击后立即在当前阅读流程中显示导出进度并阻止重复提交，不能仅依赖页面顶部、用户可能看不到的提示。成功后显示可选择的完整本机路径，并提供打开文件和复制路径等操作。宿主打开请求需使用已核对的绝对文件路径；消息已发送或打开排队不代表文件已显示。剪贴板不可用时保留可选中的路径供手动复制。

作品、阅读会话或当前选中章节发生变化后，晚到结果不能显示成新章节的导出成功。新版本尚未加载、工具不支持、权限失败、字节不符等情况应在当前可见位置显示错误。响应未知时保留原准确引用、摘要和操作号，先核对或以原请求安全重试；确定文件名和不覆盖规则防止重复生成或覆盖用户修改。

导出文件是本机阅读副本，编辑这个文件不会自动回写小说、剧本、云端工作稿或批准记录。需要继续创作时仍使用 [文本编辑、云稿与讨论流程](integration-1.9.3.md)。

## 验证边界

回归覆盖准确历史版本、较新候选并存、BOM/换行与 Unicode、同请求复用、现存文件冲突、目录链接与权限失败、并发或中断、缺少项目及旧 schema 不迁移、当前可见反馈和跨项目晚到响应。所有测试使用明确 test_only 合成目录。

发行验收须从实际安装副本的 stdio 发送导出请求，检查返回路径的 `.md` 文件真实存在、字节与原文相同，并核对作品登记库摘要不变。代码测试、真实文件落盘、宿主打开文件、原生面板目视及真实作品使用分别记录；不能把一层通过扩大成其他层已验收。
