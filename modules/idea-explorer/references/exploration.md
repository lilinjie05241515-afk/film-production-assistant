# 方向探索与碰撞

先复述当前想法的核心意图和已知偏好；不必把模糊点全部问清再开始。注明哪些内容是用户原话、哪些是你的解释。选择少数最能扩大空间的视角，而非机械轮询角色。

## 找到真实差异

可从下列维度改变一个或几个关键变量：

- 对象与场景：谁在什么时刻需要它；是否更适合另一类人或另一种使用场合。
- 核心机制：用户做什么、系统或作品怎样回应、价值如何发生；是否可以去掉中间环节。
- 表达与体验：同一主题是否可以通过不同视角、冲突、媒介、互动和情绪节奏成立。
- 价值交换：谁得到什么、谁付出什么，是否需要商业化；不要替用户默认盈利目标。
- 反向限制：移除最醒目的功能、降低规模、延迟某一步、改成不用开发的方式，方向是否反而更强。

根据想法规模给出适量方向，通常少数可比较的方向比大量浅层点子更有用。每个方向用具体机制解释“发生什么”，不要只给标签或营销形容词。区别不足就合并表述，不能假装完成多视角。

## 多轮保持横向发散

每轮先读当前阶段、已经提出的分支、用户新增的偏好和明确排除项。开放阶段把新回答当作拓展方向的材料，寻找还未尝试的机制、关系结构或视角；不要把用户对某问题的回答当成选定信号。提出过的方向可以继续保留、变体或交叉组合，记录差异来源，不靠重复措辞凑数量。

例如一个“旧友重逢”的短剧念头可以从互相隐瞒、身份错认、共同债务、利益反转或旁观者误读扩展。用户说更喜欢喜剧，只改变偏好；可以继续探索不同喜剧机制，而不是立即写某一条的全剧大纲。具体例子只是候选机制，不替用户设定题材或创作规模。

开放状态允许说明一个片段为什么成立、两条路径哪里冲突、某个限制会怎样改变体验。这种必要解释不等于全局深入。完整人物体系、全剧结构、密集逐场展开等系统开发等到用户选定；用户明确要求局部试聊时，仅深入本次指定范围。

## 比较与碰撞不强制收敛

比较时选最有分辨力的维度，例如情绪体验、人物关系、观众视点、冲突来源或表达张力；按问题需要再讨论成本、资源和验证。不要在开放探索初期用未经确认的预算、市场评分或制作难度筛掉所有大胆方向。没有证据的评分写成假设或未知，不制造精确总分。

至少让重要方向相互作用一次：A 的优势是否建立在 B 正要去掉的约束上；A 的机制和 B 的对象结合是否成立；组合是否增加新成本、稀释特色或产生矛盾。组合必须说清保留什么、舍弃什么和新假设，不能简单把全部功能相加。

挑战格式可以是：“你希望 X，同时选择 Y；根据已知 Z，这可能产生 W。我建议试 A，因为……；若你仍偏好 Y，可以保留，但应接受……”。无证据时明确这是推测，并提出如何查证。

不要借“敢于挑战”贬低用户或反复争辩。用户明确选择后，记录准确分支、版本、原话与依据，保留有意义的异议，按选择继续；只有用户要求重新发散，或新增证据带来实质影响时才重开已结束问题。选择组合时先说清选的是哪些分支的哪些机制，不能把全部旧候选混成一个新决定。

## 阶段切换由实际意思决定

| 用户的实际请求 | 接续方式 |
| --- | --- |
| 回答问题、补充偏好、喜欢 A、继续、否定 B | 保持原阶段；开放状态继续提出不同路径，不推断 A 获胜 |
| 明确选定 A 或准确的 A+B 组合 | 保存选择与原话，沿选定方向深入；不自动批准或制作 |
| 本轮想深入看看 A，尚未选定 | 记录 preview，只深入指定范围；原选择、其他候选和阶段不变 |
| 回到开放探索、另找方向 | 显式 return_open，旧选择作为历史保留，不删除旧分支 |
| 暂停、之后恢复 | 保存暂停前阶段；恢复只回到已有阶段，缺来源不猜 |
| 明确要求制作已有方案或给定成果 | 按实际任务和已有授权进入，不强制经过脑暴或索要固定口令 |

这张表用于理解上下文，不是关键词识别器。程序没有自然语言意图判定器；宿主不能仅因字段写了 select 就声称用户选择已经过身份或语义认证。需要区分但没有证据时保留未知并核对相应原话，不把模型总结补写为用户原文。

## 合理结束状态

- 仅登记：保留原话，无下一步。
- 继续探索：保留本轮建议、分歧和可继续问题。
- 多方向并存：给各分支稳定标识，不能强行选胜者。
- 已选择方向：保存具体选择及原话；是否规划、立项或执行分别判断。
- 暂时搁置或否定：保留原因和替代，不删除历史。

只在有帮助时询问用户更在意哪种取舍；不要每轮固定要求“选一个”，也不要因未选择就认定探索失败。
