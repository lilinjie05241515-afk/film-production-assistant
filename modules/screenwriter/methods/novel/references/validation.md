# 出稿效果实测

只在用户要求测试、比较、回归或验证稳定性时使用；普通小说出稿不附评测流程。

若测试显示单次出稿仍反复出现同类问题，按 [小说 Agent 工作流](agent-workflow.md) 分离写作、机检、独立读稿与定向修订，保留每轮证据。

## 先冻结比较条件

在看候选结果前固定题面、已知事实、字数口径、版本、模型设置、可接受的结局和评审标准；按 [篇幅与文体](form-and-style.md) 区分短篇完整性、长篇跨章发展、连载追读与风格辨识，不用同一套钩子目标验收所有形式。保留一部分未参与修改的题面作最后复测。旧版 Skill、更新版 Skill、无 Skill 对照若要比较，应尽量用同一题面和相近生成条件，保存完整原稿和修改记录。已有网文作品只能作阅读参照：注明作品、公开章节链接和所比较的场景机制，不用不同题面的词频或热度推断哪篇写得更好，也不模仿特定作者。

## 把检测分层

1. **自动硬检查**：用 `novel_tool.py check` 核对汉字数、锁定原句、明示禁词和相对时间词；系统资源用 `ledger`。按题目另核对文件存在、段落提取和约束格式。失败则修正文再复跑。
2. **自动候选提示**：解释性连接词、段首同一主语、直接对白占比或结尾总结句可用于定位复读位置，不能作为小说感的通过分数，也不能据此机械增加对白、感官词或短句。
3. **逐篇语义复读**：核对视角人物当时能知道什么、物件位置与转移、人物行动动机、题材规则和结局。找出旁白是否替读者判定线索、复述刚演过的动作，或把场景卡按顺序写成办事记录；引用具体句子决定是否改写。
4. **独立阅读比较**：打乱版本标签，让未参与该篇修改的读者或独立评审者先自然阅读、再核题面；把叙述距离、语言节奏、人物声音、对白功能、开场问题、过程变化、局部兑现、结尾承诺、题材趣味与继续阅读意愿分开记，并给出证据句。连载稿按 [web-serial-writing.md](web-serial-writing.md) 复读；模型评审可帮助筛选，但不能替代真实读者偏好，也不能单靠作者自评宣布胜出。

## 迭代与报告

对重复出现的失败类型做小范围修改，再用原题和保留题复测；保留每轮原稿、自动结果、具体失败句和修订说明。目标应在测试前写明，例如硬约束全部通过、保留题无严重视角或连续性错误、独立比较未显示叙述距离退化。若若干轮后仍有反复失败，就如实报告不稳定的题材或条件，继续针对该类型修改；不要把一次全绿或一次喜欢说成普遍稳定。

多题材测试还应横向读人物：遮去姓名和设定词后，主角的欲望、风险偏好、说话策略、胜负与关系结果是否仍可区分。若都靠理性体贴地折中并约好再合作，记录具体句子和题面是否本来如此，再决定改个别正文、题材策略还是通用规则。区别不能靠强制每篇吵架、安排反派或统一制造代价来凑；评审要说明人物为何以当前方式处理冲突。
