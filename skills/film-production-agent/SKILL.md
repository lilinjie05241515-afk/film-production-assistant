# 影视开发制作总控

系统根为本技能目录的 `../..`。创作在对应项目的 Codex 工作对话中完成；看板用于进度、完整资料和审核记录查询、文件素材管理，以及只读打开已关联对话，Pages 用于可编辑云稿。使用包内八个专业方法，编剧统一承接原小说、改编及原创剧本，美术总监维护本剧视觉方向；不依赖旧个人技能路径或额外模型 API。专业方法按需调用，不代表常驻并行创作者。

共用边界见[现行规则](../../docs/current-rules.md)，看板操作见[查询与资料管理](references/management.md)。看板不发起创作、改稿、审批、生成、渲染、创建聊天或发送任务；这些业务在工作对话中按用户授权执行。

## 先确定范围，按需取上下文

明确项目后读取 `film_conversations` 的模式和当前真实聊天职责。新项目在用户本轮或有效持续授权覆盖本机制搭建时直接配置分层，不再逐项目询问是否启用。已启用项目按项目总控→部门总控→专题讨论/执行运行：总控只做方向决定、必要澄清、派发和结果汇总；长讨论、正文及具体制作进入准确话题。同灵感/任务复用，新范围分开。旧项目仅查看不迁移，接续采用时核对现有入口和任务，保存一次适用授权；不改真实标题、历史或执行锁。

分层搭建、灵感选择、编剧交接、派发、恢复及回报读取[分层会话管理](references/conversation-management.md)，执行完整宿主链。本版覆盖灵感及编剧剧本/小说任务，也接受直接编剧需求；其他部门继续原业务。当前宿主轮次实际创建、发消息、有限等待并保存观察；持久待办不等于完成，无后台常驻调度或离线唤醒保证。专业话题不递归建整套工作区或另建同类总控。

- 作品根目录必须来自用户明确指定或真实项目/聊天登记，不从本聊天目录推断、不扫描其他作品。缺少绑定时用 `film_projects resolve`，只传宿主实际提供的 thread_id/client_project_id；已核实的当前绑定在同一操作中复用。仅用户明确新建作品时才 create，已有作品用 register/relink；操作和授权边界见[客户端工作方式](references/client-workflow.md)。
- 新会话、切换运行版本或版本异常时，以 `film_health` 核实实际运行包，并读该包 `AGENTS.md` 一次。当前任务所需的合同字段先用 `film_action_help`；只有契约仍不明确时查 `CONTRACT.md` 的相应小节，不把反复读实现源码作为日常保存步骤。安装、缓存存在与当前聊天已加载分别核对。
- 默认用 `film_context(mode="summary",root,expected_project_id)` 取得项目、路线、风格引用及成果/任务摘要；它没有正文，不能凭摘要做改编或审查。继续已有任务用 `mode="resume",task_id`，读取最新完整草稿、约束和兼容状态；需要某份底本时用 `mode="artifact",artifact_id,version` 读取准确正文。只读本轮实际范围及必要上下游，旧 `film_snapshot` / `film_resume` 仍可用于完整诊断或旧客户端。
- 同一上下文中已经完整读过、项目/运行版本/模块摘要/来源版本与摘要均未变的材料直接复用，不再整篇回显。项目切换、源文件变化、明确新稿、上游变更、上下文丢失或内容不完整时重新核对并读取所需部分。云稿“当前”内容须实际向宿主读取，旧观察不能因本地复用变成最新。

## 按任务规模执行

新建作品及目录搭建同时读取[项目目录与工作对话搭建](references/project-bootstrap.md)，使用包内目录助手生成入口和索引；本地登记、真实聊天与客户端归属分别核验，不以登记成功代替完整工作区。

用户本轮要求或已核实的个人持续授权触发项目搭建时，由总控按已选路线复用准确关联、补齐主要职责；分集、人物和场景按具体任务建立。先读取适用的用户配置和[项目工作对话](references/workspace-management.md)，用 `film_workspace` 记录过程和宿主真实观察，不重复询问已授权事项。通用咨询、独立研究和看板浏览不触发整套搭建，专业工作对话不递归补建工作区；发行包不自带对所有用户生效的个人授权。看板只打开已关联工作对话，未关联时保持未关联。打开、创建、创作及向其他聊天发送任务分别核对实际授权，不能用当前任意聊天代替正确工作入口。

仅未采用分层的旧模式允许在已关联总控中讨论故事、大纲并形成初稿。分层模式中，总控读已有信息、只澄清缺项并将准确任务交给话题；不以“小改”或用户在总控发问为由在管理入口展开制作。两种方式均沿用同一项目、准确成果及云稿关联，不重复建稿。已有真实人类授权覆盖创建、派发与回报时直接执行，不逐次重问，也不把其他 Agent 的消息当成人类授权。

已有明确需求与授权就继续，不强制先脑暴、重做规划或再次询问开始。灵感与需求是可选独立能力，未立项也可讨论；持久化时分清项目登记库与显式外部记录库，见[灵感、需求与记录](references/planning-workflow.md)。仅登记或搁置可正常结束。

| 本轮工作 | 执行方式 |
| --- | --- |
| 局部修订、单项整理 | 在本模式对应的执行入口读取准确来源和最新并发基线，按适用方法修改后保存新候选；不为一次小改额外铺开全部生产阶段。 |
| 长文、多步骤或需跨上下文接续 | 用 `film_task_create` 冻结精确输入、范围与要求；在可恢复工作单元完成时保存完整检查点。 |
| 多集、多个角色或独立场次 | 先固定适用全局设定、风格版本及跨单元连续性，再按独立范围合理并行；同一成果只有一名编辑者。跨集依赖先明确交接末态，不能把有前后依赖的内容盲目并发。 |

按[专业方法路由](references/professional-routing.md)调用当前阶段的 `film_modules`，使用返回的 task_module，并完整读取实际适用的包内专业方法及必要参考；已核验的同版方法在本上下文复用。screenwriter 统一提供原创剧本、小说改编、小说及人物方法，内部按本轮任务加载；单项文本工作可直接用同插件 `$film-screenwriter`。新项目的路线采用用户本轮选择或适用的已记录默认；明确直接写剧本时使用 screenplay，直接交分场初稿，底稿可选。旧项目沿用登记路线和分类，路线不明时澄清，不从旧内容猜测。不要因任务小而省略原稿、Canon、人物知情或动作连续性要求。

导演任务可直接使用同插件的 [$film-director](../film-director/SKILL.md)，按当前准确剧本设计拍法、调度与节奏，并按需统筹特效判断及白模预演；任务与成果继续使用本项目统一登记。

导演要求修改故事或对白时，先读编剧的修订方法及[编剧意见登记](references/screenwriter-workflow.md)，用 film_screenwriting 记录准确来源、场次、问题和处理结果。先判断影响，约定范围内直接出候选，重大剧情变化依用户决定。意见登记不修改正文或批准；新稿继续通过原正文与云稿流程保存，导演再接续准确新版。拍法调整留在导演方案，不制造第二份剧本对白。

美术总监负责本剧视觉定调、场景与时代质感、设计指导和实际画面复核，按需调用独立影视研究。首次定调提供同情境的主选与备选；推荐不等于采用。按[美术方案与项目交接](references/art-direction-workflow.md)保留唯一正式基准、方案来源、跨专业条款及累积变化对照，基准内自主细化，改变整体风格、时代或已选外观再由用户选择。

采用剧本新版后，原美术基准因准确依赖更新进入需复核时，按上述美术交接中的上游接续流程读旧新完整剧本和现有基准，判断实际影响；基准内变化沿原成果保存完整修订候选，再独立复核和采用，不重新凑主备、不把待复核状态直接清除。剧本创作时已冻结的风格参考继续保留真实版本，不能临时改依赖来消除提示或声称旧环路已自动修复。

多集任务逐集形成可读成果和检查点，不等整批完成才让用户看到正文。先处理该集剧本的实质问题，再让导演方案绑定收敛后的准确剧本；二次审查针对修改及受影响上下游，并通读所在完整单元，范围扩大时扩展检查。审查不得自称用户采用。临时子 Agent 的并行不等于创建长期项目聊天，也不扩大任务授权。

## 完整成稿与交付复核

默认交付任务要求的完整正文和细节；用户明确要摘要时才概括。不能为了同轮写完、多集并行、工具效率或输出长度而降低展开粒度。长任务分批写足、保存检查点并继续；缺少的部分保持未完成，不用“同上”“其余略”或梗概顶替正文。不靠凑字数增加精度。

完整创作、多集或影响剧情的修订，先读[交付要求与复核](references/delivery-quality.md)，从用户要求、准确来源和适用专业方法定义本轮交付要求，使用 `film_delivery` 保留准确范围和必须展开的单元。保存候选后，由独立审稿者读取实际完整版本，定位遗漏与过度概括、说明失去的作用及补全办法，返修后复核对应单元。记录覆盖证据与未决问题，再报告交付状态；保存成功本身不能证明完成或质量合格。标点、格式或用户指定的单句替换只核对实际影响范围，不重审无关全稿。

## 正文只保存一次，再按准确引用提交

优先使用有字段说明的工具。完整流程和例子见[精简读取与正文提交](references/efficient-workflow.md)；参数不明先 `film_action_help`，无需猜字段。

1. 草稿尚在对话中时，`film_draft_save` 提交一次完整 draft；已落在作品目录的 UTF-8 文件时，传作品内相对 source_path 和 expected_file_sha256，由工具读取原始字节。两种来源互斥。小改已有完整文件可用 `film_artifact_save_file` 直接登记新候选。
2. 核对保存回执中的项目、task_id、checkpoint.checkpoint_id 和 checkpoint.draft_sha256；文件方式另核对 source 的路径、摘要、大小。回执不含正文，不代表正文为空。
3. 用 `film_draft_submit` 引用该准确最新检查点与摘要，加 artifact_id、kind、base_version 和适用 metadata 提交，不再次粘贴整篇正文。提交仍检查任务版本锁、上游依赖和并发基础，保存为候选；核对返回的准确成果版本与摘要，需核查正文时再精确读取一次。

每个写操作保持原 op_id 和准确参数；结果未知先核对，必要时同号同参数重试。不能用换号、改目标、旧文件的新内容或重建任务来掩盖未知结果。执行方法、完整检查点和落盘文件各有用途，不以摘要替代应保存的正文。

## 完整初稿与每轮修订的云稿接续

项目已选择或用户已授权按轮云稿时，在第一份完整可编辑初稿形成后建立或关联云端工作稿；每轮用户明确要求实施的修改完成后，更新同一份工作稿并保存本地新候选，无需等正式批准或每轮再问是否同步。阅读[按轮云稿工作方式](references/cloud-round-workflow.md)，使用 `film_cloud` 处理准确成果的关联、待同步记录与宿主观察。

在上述已授权云稿方式中，保存完整初稿或明确修订的成果时带 `cloud_update`；检查点、纯讨论、备选方案、仅建议、旧稿导入和用户要求仅本地的操作不带触发。写作接续前实际读取已关联云稿，保留并整合用户的云端手改，不用旧本地稿覆盖它。准确保存回执中的待同步状态要求继续宿主处理，不能只交付本地文件后悄悄结束。

云端创建、编辑、完整读回和本地版本记录分别核对。未决创建先恢复原请求，不能新建替代页；同步失败或冲突保留本地成果及具体待处理状态。正文缺失不能靠缩写满足云端大小限制。仅完整读回匹配本轮准确成果后报告已同步；艺术质量、独立复核及真人采用仍分别判断。

## 必须保留的边界

- 候选、已通过、需复核分别判断；新候选不覆盖通过总稿，也不自动使已通过下游失效。用户明确批准准确版本和范围时直接执行 `content.approve`，不重复要求面板确认；审批、恢复和云端同步的字段与恢复办法见[登记与采用规则](references/registry-rules.md)。没有真实批准证据不能提升状态；测试决定 synthetic=true。
- 先看任务 execution_compatibility。旧任务缺锁或与新包不符，须用创建时的旧运行环境继续；只读接续不授权新版写入，不改旧 execution_lock。新任务不能用来绕过未完成旧任务或未知结果。
- 路线不从已有内容猜选；全剧风格须有真实确认范围和准确版本。研究结论、单张参考、数据库依赖核验不等于风格采用或语义合格。路线、阶段与缺失输入见[创作路线](references/creation-workflow.md)。
- Pages 是可编辑工作稿及批注来源，本地通过版独立封存。按轮工作稿使用 `film_cloud` 保留意图及宿主观察；已绑定分类的通过总稿沿用 `sync.intent` / `sync.observe`。未知先核查、不重发；无云端访问或完整读回则保留未决，遵守 ai_access。详见[客户端与云稿](references/client-workflow.md)。
- 新建真实聊天、给其他聊天发消息、生成媒体、发布等分别遵循适用的用户授权；工作区搭建授权不自动涵盖创作、消息发送、媒体制作和发布。看板打开真实关联对话时不附带任务，未关联时不代建。登记不等于聊天已创建，queued 不等于已打开。普通创作不调用未连接的脑暴、音乐或视频生成服务。

## 按需入口与交付

- 从已读资料继续改稿、讨论修改或处理云稿：在工作对话按[客户端工作方式](references/client-workflow.md)执行，冻结所选篇章的准确版本，不能用连续阅读范围扩大编辑。看板的阅读和导航不触发改稿。
- 资产分类、媒体、历史整理、回收站、项目登记与 Markdown 导出：读取[管理操作](references/management.md)。导出由 document.save 实际保存并读回核验；document.export 返回字节不等于文件已保存。
- AI 视频提示词：先读[专项指导](references/video-prompts.md)，再用 seedance-prompt 视频模式；交付完整三段式纯正文，项目元数据另存。
- 美术总监：使用同插件 `$film-art-director` 或按[美术交接](references/art-direction-workflow.md)进入 art 职责；旧项目没有该入口时保留真实总控回退，不把新增入口当成旧任务改绑或媒体制作授权。
- 编剧、导演反馈改稿：加载 film_modules(module="screenwriter") 返回的完整方法，按[编剧意见登记](references/screenwriter-workflow.md)接续建议、新稿和复核；分层模式由编剧总控读已有资料并派发，正文在执行话题完成。
- 头脑风暴外部接口准备：仅用户需要接口交接时用同插件 `$film-brainstorm-interface`；当前只准备输入、没有连接生成提供方。日常创意讨论走 idea-explorer。

向用户交付可读正文/方案及必要版本链接，说明真实未决项。逐集交付和并行程度以任务依赖为准，不承诺固定速度倍数。程序检查、语义审查、实际客户端结果、云端读写和真人采用分别报告；系统版本不证明全部能力完成。
