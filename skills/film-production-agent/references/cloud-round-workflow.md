# 按轮云稿工作方式

用于已明确作品中的大纲、小说、人物小传、剧本、导演方案、特效与提示词等完整文本。云端工作稿从初稿阶段开始使用，可以尚未审核；批准、制作和发布仍由各自的真实请求决定。此流程由正在执行任务的宿主推进，没有后台实时监听或自动双向合并。

## 触发时机与范围

本流程适用于用户已选择或已授权的按轮云稿方式：“总控讨论 → 第一版完整初稿 → 在同一云稿中持续修改”。已有适用授权直接沿用；通用发行包不把某位用户的个人默认授权自动授予其他使用者。总控对话可直接讨论和整理大纲；专业工作对话沿用项目、成果与云稿身份，不另造文档。

| 本轮内容 | 处理 |
| --- | --- |
| 比较方向、讨论某段可如何调整、只给意见 | 保留讨论结果，不改正文，不准备云写入。 |
| 明确要求整理完整初稿 | 完成准确范围的完整正文，保存候选并准备云稿；无需等用户正式批准。 |
| 明确“按这个改”“采用第二种写法”等实施要求 | 以当前云稿及必要底本为基础修改，保存新候选并更新原云稿；已确定目标和默认规则后不重复询问同步许可。 |
| 任务中间检查点、旧稿导入、仅登记或浏览 | 保存或读取其自身记录，不用它们冒充完整初稿触发云稿创建。 |
| 用户明确仅本地、不上传或暂停云稿 | 保留本地成果，按该范围的本地模式处理；不通过其他保存路径补发云写入。 |
| 用户批准准确版本 | 独立执行采用流程；既有工作稿同步不能冒充批准。 |

“完整”对应本轮约定的章、集、场或文档单元，不必等待整部作品完成；不能把缺少后半部的章节当成完整章。真实已完成的初稿可以带待改问题上云，交付质量复核继续按 `delivery-quality.md` 执行。

首次明确创作可创建当前准确成果的私有工作稿；若用户已指定可写 Space 或父 Page，则使用其真实身份。不要把软件升级、初始化聊天或恢复登记当作批量上传旧作品的请求。工具或账号限制导致不能创建时保留本地版本和待同步状态，不临时改用其他外部服务。

## 每轮开始先读当前稿

1. 核实本轮项目、成果 ID、范围和任务兼容性，读取 `film_cloud` 的准确关联及未决记录。字段从实际工具 schema 或 `film_action_help` 获取，不能猜事件名或参数。
2. 已有关联 Page 时，实际读取当前正文与相关批注，保留 Page ID、完整区块、哈希、可用的 sequence 和观察时间。完整云稿读取可复用于本轮编辑前核对与本地观察；不要反复读取无关历史。
3. 若云稿包含尚未接入本地的手动修改，先完整保留云稿观察，并将准确范围另存为本地候选；以此与用户本轮要求整合。用户手改不是等待被旧本地稿覆盖的临时噪声。云稿和本地都有独立改动、且合并意图不明确时保留两边版本并指出具体冲突。
4. 未决创建或编辑先核查原请求是否已生效。同一次云操作未知时，不为新版本重新建页、改目标、重置请求标识或声称失败。可以继续独立内容的工作，受影响范围保持未决。

准确成果关联优先于分类总稿绑定。一章的工作稿不能自动认领整部小说 Page；仅凭标题、类别或“最近打开”不能认领已有页。已有多份明确来源需要确定当前成果的目标，而不是猜一个覆盖。

## 保存完整成果并继续处理待同步

正常完整初稿和明确修订，在 `film_artifact_save_file`、`film_draft_submit` 或旧保存动作允许的位置带 `cloud_update`，记录触发类型与本轮真实要求；使用当前工具定义的字段和枚举。用户要求仅本地时不加云触发并遵守已记录的本地模式。检查点本身不触发。

`cloud_update` 的触发值为 `full_draft` 或 `confirmed_revision`，并带 `user_request={source,reference,quote}`：当前工作对话请求使用 `source=conversation`；`panel` 仅保留为历史请求来源兼容，不开放当前看板云写入口。reference 指向真实请求，quote 保留用户实际要求，不代写不存在的授权。`local_only` 可明确记录仅本地的本次保存，不产生云写入。恢复到旧调用不应使本地模式失效。

已将当前云稿作为修订底本时，带 `base_observation_id` 指向该准确成果最后一次完整观察。先用 `cloud.bind` 保存真实完整观察、取得该 ID；不得填另一个 Page、另一成果、旧观察或编造的 ID 来跳过云端差异。

核对保存回执中的准确成果 ID、版本、SHA-256 和云稿待处理记录。正文已保存时，通过准确引用继续准备，不再次写入相同正文来制造一个版本。`film_cloud` 只持久化计划、关联和宿主观察；回执中的“已准备”或“待同步”并不意味着远端已执行。

宿主在本轮继续完成已授权云稿任务；不要只保存本地文件后默认结束，也不要把每次同步都变成新的用户确认。因访问失败、冲突或未知无法完成时，交付本地完整成果、目标云稿及实际待处理原因；以后从同一记录恢复。

### 工具契约与当前状态

`film_cloud` 使用 `root`、`action`、`payload`。read 需要 `expected_project_id`，可用 `artifact_id` 缩小范围、用 `observation_id` 读取某次完整来源；write 另外需要 `op_id`、当前云稿状态的 `base_revision`。这个 revision 来自 cloud.read，不能拿成果 version、Page revision 或项目设置 revision 代替。动作的完整定义见 `../../../docs/integration-cloud-1.12.0.md`。

| action | 用途 |
| --- | --- |
| read | 返回 policy、准确 documents、jobs 及 next_action；只读状态不是实时云内容。 |
| configure | 按用户选择设 `mode=round_end/local_only`，可设创建目标 `destination.kind=private/space/page`；私有目标无 id，其他目标需要真实 id。 |
| bind | 对最新准确 `artifact={artifact_id,version,sha256}` 保存完整 Page 观察，建立首次准确关联或刷新同一 Page 来源；不替换已有 Page，不认领分类总稿 Page。 |
| prepare | 针对准确成果和 trigger/user_request 准备云任务；正常保存已有 cloud_update 回执时复用该 job，不另造相同任务。 |
| record | 按实际宿主事件登记 job_id、event 和 observation；所有事件都带原 job.request_id。 |

常见 next_action 为 `claim`、`preflight`、`readback_existing`、`recover_creation`、`resolve_previous`、`reconcile_cloud_changes`、`prepare_retry`、`local_only` 或 `done`。按实际返回推进；unknown/requesting/awaiting_readback 都先恢复，不能重新领取。旧版先前已发出的未知请求不因新稿排队而被消除。

完整 Page 观察含 `source:"host_tool"`、`tool:"read_page"`、实际带时区 `observed_at`、真实 `page_id/page_url`、完整 `content`、`whole_page_complete:true` 和 `revision`。没有实际修订号时传 null，不将 sequence 或本机版本擅自改名为服务端修订号；可用 sequence 留在原 Pages 工具观察，用于实际编辑保护。content 来自本次完整正文，不是拟发送稿或为了通过摘要校验而重构的文本。Pages 分块或换行规范化导致差异时保留真实差异，不篡改读回；经核对需要采用规范化文本时另存明确的新候选及新同步记录。

## 首次建页与同页编辑

首次创建前先持久化准确请求和稳定创建键，再领取本次宿主操作。只对本轮新取得执行权的待建项调用 Pages `create_page`；先读状态、后领取，同操作号的缓存回执不能被当成再次创建的许可。

领取使用 `record(event="request_started")`；准备目标已有 Page 时，先实际读取并 `record(event="preflight")`，确认 next_action 允许领取。preflight 已发现云稿恰好等于准确目标时会直接 synced，无需重复写入。新 Page 创建结果以 `page_created` 保留真实身份，随后 `verified` 完整读回；编辑后同样以 verified 核对。未知结果记 unknown；只有实际确认没有发生写入才可用 failed 的 `no_write_performed:true`。发生未决外部写入后，不能只用 conflict/failed 声明跳过完整读回。

保留同一次 `create_page` 的 `title`、完整 `initial_blocks`、目标位置与 `idempotency_key`。没有指定位置时可创建私有 Page；Space ID 只能填 `space_id`，真实父 Page ID 才能填 `parent_page_id`。创建返回真实 Page ID 后马上保留关联，再完整读回。创建回执或页面链接本身不证明正文已同步。

创建结果未知时先恢复原请求。只有当前工具明确支持对该创建安全重试时，才能复用相同键和完全相同参数核查；不得另换键、标题或位置创建替代页。工具能力不足以确定原结果时保留未知，不能凭相似标题认领一个 Page。

已有 Page 的修订沿用该真实身份，并在写前刷新受影响区块。使用真实 `block_id`、`expected_hash` 和可用 `base_sequence`；记录具体修改范围，保留未修改正文及批注。不用本地通过总稿整页覆盖工作稿，不把普通工作稿绑定变更成 `master.bind_page` 分类总稿绑定。

Pages `edit_page` 操作使用 `op`，不是 `type`。修改已有文字可用带准确原串的 `patch_block_markdown`；新增、分段或结构变化使用对应非 patch 操作。遵循工具的批量限制，不混用不允许的操作。`initial_blocks` / Markdown 编辑与实际 Page 分块可能不同，读回按真实区块核对，不能捏造块 ID。

检查整次 `commit_status` 和每项结果。partial 结果先读回，只重新准备未应用且仍有需要的部分；已 applied 或因 block_deleted 被忽略的操作不重复发送。unknown 先同一正文流读回并比对原计划，不把缺少成功回执当成未写入。大文档分批保留完整内容和进度，不能删减正文、改用摘要或丢掉批注来绕过大小限制。

## 完整读回与本地记录

云操作后完整读取当前正文及相关批注。`view=full` 或完整 `editing` 观察必须具有准确 Page 身份和完整区块；有 selection 时 `whole_page_complete` 必须为 true。局部搜索、excerpts、截断结果、页面打开成功、创建回执都不能当成完整读回。

核对当前工作稿与本轮准确保存内容及允许范围，使用 `film_cloud` 记录实际观察。只有完整读回满足当前意图后才报告该准确版本已同步；不匹配保留差异或冲突。云端修订号缺失保持未知，不拿本地版本号或内容长度代替。

Pages 可能把连续列表项等 Markdown 拆成独立块，并调整块间空行。遇到摘要不同，先保留完整观察与原候选，逐块核对文字、顺序、代码内换行及批注。确实只存在平台排版规范化时，把实际完整云稿另存为同一成果的新候选，在 metadata 记录旧准确版本、观察 ID 和“仅云端排版对齐”；沿用本轮真实要求，带 `cloud_update` 及该 `base_observation_id`。重新实际读取并对新请求执行 preflight：云端已等于这个新候选时直接完成，不再编辑云端，也不把旧版本标成已同步。存在文字、内容顺序或实质差异时继续保留冲突；不能用去掉全部空白、摘要或近似匹配代替完整核对。

将同一次完整宿主观察交给 `film_pages_import`，刷新看板中的工作稿；这一步不再次联网、不直接批准，也不能把旧观察说成最新。导入前核对明确 root 的项目身份；原导入工具没有 `expected_project_id` 参数时，不伪造该字段。必要的版本候选与云稿观察分别保存，不把观察自身当成正式正文批准。

交付时区分本地候选版本、云稿目标及已读回的版本、尚未同步的修改、质量复核和用户采用。打开云稿的 `queued` 仅代表宿主已接收打开请求。不得把本地合成测试、开发安装或宿主自报身份写成真实云端全流程验证。

## 与通过总稿的关系

按轮云稿使用 `film_cloud` 对准确成果的关联和日志。已有分类通过总稿仍沿用 `master.bind_page` 与 `sync.intent` / `sync.observe`，参见 `../../../docs/integration-pages.md`。同步成功不会自动批准，用户批准成功也不会消除尚未完成的云同步。

正式采用新版本后，只按既有依赖规则标记受影响内容需要复核，不自行重写下游小说、剧本、导演方案或提示词。云稿存在用户尚未采用的内容时先保留它，不能以正式采用为理由无条件覆盖整页。
