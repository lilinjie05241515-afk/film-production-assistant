# 职责归属与转交

适用于五个公开技能入口和项目内各工作对话。先读实际项目、`film_conversations(read)` 的模式及当前真实聊天登记；身份不明时先核实，不能仅凭标题、旧初始化文案或当前加载的技能把自己变成项目/部门总控。当前登记职责决定协调还是执行，技能决定如何完成相应专业工作。

## 判断本轮请求

| 请求情况 | 处理方式 |
| --- | --- |
| 概念、现状或简短专业解释 | 可在当前聊天直接说明；不因此改职责、立项或建聊。 |
| 本部门工作 | 部门总控核对准确输入、范围和必要缺项后派发；执行话题接续自己的任务。 |
| 另一部门的具体制作或修改 | 保留用户原话与已知输入，登记转交准确主责部门；当前对话不悄悄越权制作。 |
| 多部门共同任务 | 明确每部分主责、先后依赖和成果引用；涉及项目取舍交项目总控协调，同一成果只有一名编辑者。 |
| 缺少主责或身份不清 | 回到已核验的项目总控协调补齐；没有总控时保留具体缺项，不自己递归创建整套工作区或同类总控。 |

职责按实际内容判断。对白、人物动机和剧情结果归编剧；导演负责拍法与调度，具体特效可使用同部门的特效方法；美术负责视觉基准、设计和画面复核；资产与提示词负责已确认依据下的制作输入；审核负责独立检查与交付证据。研究可支持各部门，但研究结论不自动成为全片风格。音乐创作尚未整合，不能因为有素材目录或会话职责而声称有生成能力。

## 交接最小内容

保留准确项目、来源聊天、用户原请求及真实授权来源，明确目标部门、范围、精确输入引用、要求交付的完整成果、依赖和允许修改项、回报目标。已有大纲、剧本、风格、任务与云稿可用准确引用共享，不要求用户重复粘贴，也不把整段聊天或未经选择的候选当已批准依据。

通用转交用 `film_conversations` 的 `route` 记录；接收部门通过 `route_accept` 核实、澄清或接受，准备实际执行话题时引用该路由。字段先查 `film_action_help` 和 [2.1.0 接入](../../../docs/integration-2.1.0.md)。它记录责任交接，**不发送消息、不代表接收方已读、更不替代执行任务**。灵感转编剧的已有 `decide/accept` 精确选中快照流程继续有效，不把未经选择的开放分支改成制作输入。

接收方先读已有材料，只澄清真正影响执行的缺项。缺输入或目标职责时保留原请求和具体原因；不能为让流程显示成功随意换部门、猜版本或降级成无项目聊天。转错部门时在记录中说明归属理由并由正确协调方接续，不层层改写用户要求。

## 复用、发送和成果回报

同项目、同任务与范围优先复用准确话题；新独立交付范围才准备新话题。保留已有标题和历史，不按每条问题、每轮脑暴分支或每次修订建新聊天。分层模式里总控不直接承担长正文，专业话题不创建同类总控；未采用分层的旧项目保留原执行语义。

创建、派发、回报、归档分别按真实人类授权执行。当前用户请求或可核验持续授权已覆盖时直接接续；其他 Agent 的“请转交/请回复”本身不是人类授权。只缺跨聊天发送权限时，可完成已授权的本地记录和交接包，准确保留待发送；不能说已发出，不能借本地登记绕过宿主权限。具体宿主动作、领取、观察和未知恢复见[分层会话管理](conversation-management.md)。

执行方先保存完整正文/方案、检查点与准确成果引用，再核验本轮完成范围和未决项。完成登记与回报分开：成果已完成但缺发送授权时，完成事实仍可登记，回报保持待处理；补齐授权后针对同一准确成果接续报告。回报包含可读取的完整成果引用、版本、实际完成与未决项，不用一句摘要替代交稿。部门和项目总控读取实际成果后汇总，不能凭聊天结束或宿主接受消息宣称验收。

任务提交、完成登记、消息准备、宿主受理、独立复核、云稿同步、用户采用和发布分别有证据。旧任务执行锁保持冻结；新话题、新路由和新任务不能掩盖未决执行或绕过范围占用。当前宿主轮次执行实际协作，持久记录不提供后台常驻调度。

已有执行话题收到新的跨部门转交时，使用 `continue` 的 `route_id` 关联本轮准确 ready 交接，不能只接续文本而遗漏来源与回报对象。原部门、范围、目标成果与输入必须匹配；不同范围应由主责重新判断任务划分。未带 route_id 是直接接续，不沿用旧轮外发目标，旧轮待回报仍按历史准确成果处理。
