# 项目工作对话

适用于用户本轮要求或已核实的个人持续授权覆盖的项目工作区搭建，以及打开已关联工作对话。先读取适用的用户配置；已授权事项无需逐次重问，当前明确限制优先。发行包不将某位用户的默认授权授予其他使用者。看板只打开已有准确关联，不创建聊天或发送任务；普通咨询、独立研究与仅浏览不触发整套搭建。共用边界见[现行规则](../../../docs/current-rules.md)，具体字段以 `film_workspace` 的实际定义和[工作区协议](../../../docs/integration-workspace-1.11.0.md)为准。

新建作品及本地目录入口另读[项目搭建](project-bootstrap.md)，完成或部分完成后运行包内目录助手刷新项目导航和对话索引。索引是宿主观察的派生快照，不是实时聊天列表。

## 先区分会话模式

读取 `film_conversations` 的实际配置。新项目已有按本机制搭建授权时直接配置分层，不再追加开关确认。旧项目仅查看不迁移；接续采用时核对旧任务、保存一次适用授权并采纳准确主职责聊天为管理入口，保留真实标题与历史。尚未采用的旧项目继续本文件以下职责槽位与执行语义。分层讨论和制作按[分层会话管理](conversation-management.md)建立或复用独立话题；工作区搭建负责主要入口，不代替话题、派发、回报或宿主归档。

分层模式中项目总控和部门总控只做方向、必要澄清、派发与结果汇总，不在管理入口展开长正文或具体制作。灵感总控先保存原话后交独立讨论话题；编剧/小说、导演与特效、美术、资产与提示词、审核与交付等已登记部门读已有资料、补缺项后交准确执行话题。当前登记职责优先于旧初始化提示，跨职责请求按[归属与转交](request-routing.md)处理。专业入口与话题均不得递归调用 `workspace.prepare`，不得再创建同职责总控。模式采纳不更改旧任务执行锁。

## 路线与职责

先读取实际项目与登记路线；新项目可使用用户本轮选择或适用的已记录默认，既有路线保持。旧项目路线为 unset 且本轮没有选择时澄清，不从文件内容推断。novel_only 默认建立总控、灵感需求、小说人物、质量复核四类；screenplay 使用总控、灵感需求、美术总监、剧本分集、导演特效、资产提示词、质量复核七类；novel_to_screen 加上小说人物共八类。纯小说只有用户明确需要美术入口并授权初始化时，在 workspace.prepare 使用 include_art=true 增加 art 职责，共五类，不强制转影视。分集、人物、场景专属对话按后续明确工作建立，研究按主题建立。角色是工作入口，不自动启动对应创作。

老项目暂缺 art 槽位时，解析返回的 legacy_control_fallback 仅表示保留真实总控入口，不代表已建好美术对话。按适用授权补建缺项后再使用新入口；现有任务的真实 thread_id 与冻结方法优先，不因新增角色挪移任务、改旧执行锁或重建云稿。影视研究仍按主题独立，不把旧研究聊天因标题类似自动认领为美术职责。

小说人物和剧本分集职责均调用统一编剧的适用模式，既有角色槽位、scope 和对话关联保持；不为技能合并自动重命名、合并或删除聊天。直接剧本工作入口可从完整分场初稿开始，底稿可选。导演反馈通过准确成果的意见记录交接，保存记录不等于已经给另一聊天发送任务。旧任务仍在原冻结运行环境接续；美术 art 入口与基准接续不受编剧方法合并影响。

## 初始化和恢复

1. 总控是工作区的唯一搭建协调者。先用 `film_workspace(read)` 读取实际 required_roles、职责槽位与已有观察；本轮请求或适用持续授权触发搭建时 `prepare`，使用准确项目身份、当前 revision 和同一次操作号。复用已完成槽位，只处理缺项；发现搭建已在进行时核查原请求，不并发建立第二套。路线改变保留旧入口历史，不删除聊天或自动迁移旧任务。
2. 核对作品登记、全局项目绑定和宿主真实聊天。只按明确 threadId、职责和范围复用；相似标题不是关联证据。通用咨询、开发或其他作品的聊天不直接改绑为本作总控。登记已存在但未经宿主核对时保持待核对，不直接当作健康入口。
3. 创建前用宿主 `list_projects` 核实准确客户端项目及其目录与作品 root 一致；在适用授权覆盖本路线职责后，记录稳定请求并调用一次 `create_thread`。缺少对应客户端项目或宿主创建能力时，保留本地搭建的实际结果及待关联项，不把未发出的请求登记为已请求，不用 projectless 或其他项目冒充准确项目。目录存在、作品登记成功和客户端项目存在分别验证。
4. 初始提示携带项目 ID、授权作品目录、职责/范围、initialization_id、slot_id、request_id、已知总控 ID 和准确可用来源引用，要求只核对本职责关联、报告就绪并等待创作指令，明确不得递归补建整套工作区。不得因建立工作区而开始写小说、研究、生成素材、批准或给其他聊天发送消息。新聊天需读取的上下文应与职责相关，不复制整套无关历史。用户此轮同时明确要求创作时，另按实际授权执行相应任务。
5. 工具返回准备中的 clientThreadId 时只记录排队引用；取得真实 threadId 后才能记入作品对话与 `film_projects bind`。两种关联完成与 Codex 侧栏所属项目是不同事实，分别记录。记录为 host_reported 的状态是当时宿主观察，不能声称持续实时健康。
6. 创建、登记或绑定只有部分成功时，保留真实 ID 并补齐缺项，不能重新创建。结果未知先核查宿主任务或已建立的聊天，未确认失败前不重发 create_thread。操作号和初始化请求标识保持不变；不能因换聊天或重开面板重置未知状态。新建前先重新 read，只有待建且本轮首次成功领取的槽位才执行创建；同 op_id 的 request_started 缓存回执不是再次调用外部创建的许可。已请求、排队或未知的槽位只核查原请求。

把已核实属于本作品的工作聊天归入准确客户端项目，需要本轮请求或适用持续授权覆盖该归属整理；使用 `move_thread_to_project` 执行并核对真实结果。项目搭建授权不包含移动无关聊天或更改全局侧栏排序。用户自定义标题保留，不能把本地登记改名冒充宿主聊天已改名。解除关联不删除真实聊天。

排队恢复时先检查原工具回执：只有实际返回相应 operationId 才可调用该操作的状态工具，不把 clientThreadId 填入需要真实 threadId 的 read_thread/wait_threads，也不把它当作工作树 operationId。没有确定查询接口时，用 list_threads 找候选，再用 read_thread 核对初始提示中的准确项目、职责、scope 和原 request_id；初始化提示必须包含这些可核对标识。标题相似不足以认领。暂时取不到准确证据就保留排队，继续其他独立缺项，不用超时推定失败或重建。

## 打开、执行与接续

仅未采用分层模式的旧工作方式允许总控直接承接故事与大纲讨论、初版整理和已明确的修改，不强制用户为了同一轮讨论跳转。分层模式按上节将长讨论与制作交给准确话题。两种方式都按准确职责和范围接续，并读取同一成果的 `film_cloud` 关联；对话不是云稿身份，不能因更换聊天复制文档。完整初稿与每轮明确修订按[按轮云稿工作方式](cloud-round-workflow.md)继续保存和同步；初始化工作对话本身不触发建页或上传既有作品。

以本轮内容 category/stage 和准确范围解析对应槽位，优先复用专属范围，缺少时使用对应项目级职责入口。`navigate_to_codex_page` 只打开真实 threadId，不能据此声称已发送任务或已开始写作。打开失败保留旧 ID，核查是否归档、无权或已失效；不要直接造一个新聊天。

用户本轮或有效持续授权覆盖向该项目准确对话派发/回报时，用 `send_message_to_thread` 发送准确要求，不重复询问已经授权的动作；建立对话、共享成果或其他 Agent 要求回复本身均不自动授权发消息。传递项目、职责、成果 ID/版本、用户原话、允许改动、已知缺项及可核验人类授权来源。分层模式保存派发与回报待办，有限等待后核验实际结果；未知发送先核查、不自动重发。仅点击“进入工作对话”不发送消息。

看板可查询已有记录并打开关联聊天；打开操作不触发继续创作。继续写作仍检查原任务执行锁；新对话、路线或系统版本不能解除原范围占用或改写旧锁。任务状态、聊天状态、作品版本及用户采用分别核对。

本地目录、作品对话绑定、客户端侧栏归属和就绪分别记录；associated_observed 只表示已保存观察，可能仍为 host_reported_projectless，不能据此报告全部归入项目。只在用户授权范围内通过宿主完成准确归属并再次核对；不修改全局侧栏排序，不把本地登记改名冒充宿主改名。
