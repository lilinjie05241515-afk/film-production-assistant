# 编剧

本入口负责故事文本，总控负责项目与制作协作。先用 `film_modules(module="screenwriter")` 取得经校验的包内入口，完整读取其 `SKILL.md`，再只加载当前任务需要的参考。不能只凭本入口简介写作。

已有明确项目时先读取 `film_conversations` 的模式及当前真实职责，以当前登记区分编剧总控和执行话题，不按旧初始化提示或标题猜测。分层模式下，编剧总控只负责接收准确选中来源或直接写作需求、读取已有项目、只澄清必要缺项、确定大纲/正文/修订范围并派发；长篇正文与具体改稿由独立执行话题完成。用户已有明确要求时不强加大纲、脑暴或小说前置，也不重复确认已授权的创建、派发及回报。完整操作见[分层会话管理](../film-production-agent/references/conversation-management.md)；非写作请求按[职责归属与转交](../film-production-agent/references/request-routing.md)处理，简单咨询可就地解释，实际制作交主责。

执行话题先核对自己的项目、上级、准确范围、来源版本和已有 task_id，复用同任务的检查点及云稿；只执行已授权工作，不另建同类编剧总控、不递归调用 `workspace.prepare`。完成后保存完整候选及实际状态，按可核验人类授权回报准确上级；回报未决与成果完成分别保留。临时子 Agent 不代替长期执行话题，持久待办不保证后台执行或离线唤醒。

核对真实绑定及已选路线，使用总控的精确版本读取、保存、任务与云稿机制；旧项目路线不因调用编剧而改变。未启用分层的旧项目保留原专业对话语义，仅查看不迁移；采用时核对原任务并保存一次适用授权，不改旧锁。项目外的纯文本请求可直接完成，无须先创建项目。默认直接写剧本，小说创作和小说改编由用户明确材料与要求进入；已有剧本可以直接修订，不强制小说、大纲或重复底稿。

AI 短剧是优先写作模式，题材、画幅、集数和时长由本项目决定。导演意见先判断影响，在约定范围内直接交完整修订候选；重大动机、关系、事件后果、结局或世界规则变化由用户决定。沿用已有授权，不重复确认；建议来源不能自行授权。

读取当前实际正文和批注，保留人物、知情、道具和跨集连续性；使用返回的 `task_module` 与真实工具合同保存完整版本。新候选、独立复核、云稿同步和用户采用分别记录。遇到旧任务执行锁不相符时只读恢复，在原运行环境接续，不改锁绕过。独立小场景仍以可读正文交付，不输出工程表替代剧本。
